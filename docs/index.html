How it works

HaikuSonnetHuman controlGates

Dashed line: a failed line gets one rewrite with the checker's complaints. A second failure drops the account. Code checks the quote is verbatim. A Haiku checker compares the line to the quote. Both reduce invented facts; neither guarantees none. In the live run the glossier.com line added "for makeup" beyond its quote and passed, and the Harry's and Ritual lines add words the same way.

Claim checker calibration

24 labeled synthetic cases (half faithful, half with one injected unsupported claim). Model claude-haiku-5-5. With the first checker prompt: accuracy 100%, false passes 0, false fails 0. The cases are easy by design; real lines are harder, which is why the verbatim-quote gate runs first.

Real lines are harder. I hand-labeled the 30 real lines that passed (17 live, 13 held-out): 24 faithful, 6 add words beyond the quote (glossier.com, harrys.com, ritual.com, buffy.co, ridge.com, girlfriend.com). The first checker prompt passed all 30, so it caught 0 of 6. One labeler, strict reading. Source: evals/real_lines_labeled.jsonl.

Prompt fix, measured. I rewrote the checker prompt to fail any content word the quote lacks, and re-ran it on the same 30 lines (2026-10-24, claude-haiku-5-5). A first, stricter draft caught 6 of 6 but failed 10 of 24 faithful lines. The shipped middle version catches 5 of 6 padded lines and wrongly fails 2 of 24 faithful lines. On the 24 synthetic cases it has 0 false passes and 1 false fail. The prompt was tuned against these same labels, so this is in-sample. The missed line is buffy.co. Source: evals/real_lines_rescored.json (shipped), evals/real_lines_rescored_strict.json (first draft).

Limits

Some quoted lines name real founders from public homepages. Filter names before any real use.

Lines restate what a homepage says. They are an opening, not deep personalization. No contact emails are collected, so the Instantly file has an empty email column to fill from an enrichment tool. The n8n workflow ran once on 2 domains with n8n 2.44.6 (runs/2026-10-24-n8n/). The error branch, HubSpot live mode and a real approval session were not run. In that run 5 of 9 nodes executed, starting from the "Every Monday 07:00" node as the CLI start node. The schedule did not fire on a clock, and the error branch and "Run now (manual)" did not run.
